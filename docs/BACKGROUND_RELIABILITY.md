## 1. Производители и оптимизация батареи

Прошивки Xiaomi, Huawei и Samsung агрессивно убивают фоновые приложения. Полностью обойти это нельзя: надёжно работает связка из архитектуры, настроек телефона и подсказок в приложении.

### Что уже сделано в плагине
- Foreground-сервис с уведомлением. Это самая сильная защита.
- `START_STICKY`, перезапуск после перезагрузки (`startOnBoot`).
- Очередь точек в SQLite: если связи нет или сервис убили, данные не теряются и отправляются позже.
- При старте приложения `load()` поднимает сервис заново.

### Методы плагина

| Метод | Что делает |
| --- | --- |
| `isIgnoringBatteryOptimizations()` | `{ ignoring, manufacturer }` — исключено ли приложение из оптимизации батареи |
| `requestIgnoreBatteryOptimizations()` | Системный диалог исключения из оптимизации |
| `openVendorSettings()` | Экран автозапуска/фона производителя (Xiaomi, Huawei/Honor, Samsung, Oppo/Realme/OnePlus, Vivo). Если не найден — экран приложения в настройках. На iOS — настройки приложения |
| `getState().lastLocationAt` | Время последней записанной точки (epoch ms) для watchdog |

### Сценарий онбординга курьера

```ts
await bm_geolocation.requestPermissions({ background: true });

const { ignoring } = await bm_geolocation.isIgnoringBatteryOptimizations();
if (!ignoring) await bm_geolocation.requestIgnoreBatteryOptimizations();

// Показать экран с инструкцией (см. ниже) и кнопку:
await bm_geolocation.openVendorSettings();
```

### Ручные настройки на телефоне

**Для всех Android.** Настройки → Приложения → приложение → Батарея → «Без ограничений». Геолокация: «Разрешить всегда».

**Xiaomi / Redmi / POCO (MIUI, HyperOS)**
- Безопасность → Разрешения → Автозапуск → включить.
- Экономия энергии → для приложения «Нет ограничений».
- Закрепить приложение в списке недавних (замок), чтобы «очистить всё» его не убивало.

**Huawei / Honor (EMUI, MagicOS)**
- Батарея → Запуск приложений → выключить «Автоматическое управление» и включить вручную: автозапуск, вторичный запуск, работа в фоне.
- Закрепить в недавних.

**Samsung (One UI)**
- Батарея → Ограничения фоновой работы → убрать приложение из «Спящих» и «Глубоко спящих».
- Выключить «Автоматически оптимизировать» или «Adaptive battery» (либо добавить исключение).

Подробности по моделям: https://dontkillmyapp.com

### Оговорки
- Названия внутренних экранов производителей меняются между версиями прошивок, они закрытые и могут не открыться. Поэтому есть запасной вариант с экраном приложения. Список в `BmBatteryHelper.java` придётся уточнять на реальных устройствах.
- Для Google Play нужна декларация по background location и показ объяснения пользователю перед запросом.

## 2. Серверный watchdog: push, если нет точек

Сервер сам замечает, что курьер «замолчал», и пытается его разбудить. От телефона для этого ничего не требуется: он может быть заблокирован или приложение убито системой.

### Схема

```
Приложение курьера ──точки──▶ Бэкенд ──▶ таблица courier_state
                                  │       (courier_id, last_point_at, fcm_token,
                                  │        on_shift, last_push_at)
                                  ▼
                        Планировщик (cron, раз в минуту)
                        ищет: on_shift = true
                              AND now - last_point_at > N минут
                                  │
                                  ▼
                        FCM push ──▶ телефон курьера
```

### Что хранить на сервере
- `last_point_at` — обновляется при каждом запросе от плагина. Брать время из `location.timestamp`, а не время получения: после оффлайна точки приходят пачкой и со старыми временами.
- `fcm_token` — приложение отправляет при входе.
- `on_shift` — курьер нажал «начать смену» и ещё не нажал «закончить».
- `last_push_at` — чтобы не слать push каждую минуту.

### Запрос планировщика (раз в минуту)

```sql
SELECT courier_id, fcm_token
FROM courier_state
WHERE on_shift = true
  AND last_point_at < now() - interval '3 minutes'
  AND (last_push_at IS NULL OR last_push_at < now() - interval '5 minutes');
```

Для каждого найденного курьера отправить push и записать `last_push_at = now()`.

Порог (3 минуты) зависит от интервала точек. При `distanceFilter: 20` стоящий на месте курьер точек не шлёт, и будут ложные срабатывания. Решение: брать порог с запасом или включить в плагине `heartbeatInterval` (точка с заданным интервалом, даже если курьер стоит, см. раздел 3).

### Какие push слать

**Тихий (data-only), высокий приоритет.** Приложение просыпается и перезапускает трекинг:

```json
{
  "message": {
    "token": "<fcm_token>",
    "android": { "priority": "HIGH" },
    "data": { "type": "wake_tracking" }
  }
}
```

**Видимый (notification).** Показывается всегда и просит курьера открыть приложение: «Мы не получаем вашу геопозицию. Откройте приложение». Это запасной вариант, если тихий не дошёл (на Xiaomi и Huawei такое бывает, особенно после принудительной остановки приложения).

### Эскалация

| Нет точек | Действие |
| --- | --- |
| 3 мин | Тихий push: приложение вызывает `start()` и перезапускает сервис |
| 6 мин | Видимый push курьеру |
| 15 мин | Пометка «курьер не на связи» для диспетчера, запись в лог для разбора причин |

### Обработка в приложении

```ts
import { PushNotifications } from '@capacitor/push-notifications';
import { bm_geolocation } from 'bm-background-geolocation';

PushNotifications.addListener('pushNotificationReceived', async (n) => {
  if (n.data?.type === 'wake_tracking') {
    const s = await bm_geolocation.getState();
    if (s.enabled) await bm_geolocation.start(); // перезапустит сервис
  }
});
```

Это работает, пока процесс приложения жив. Если процесс убит, нужен нативный `FirebaseMessagingService`, который поднимет процесс и сервис трекинга (в плагине он есть, см. раздел 3).

### Ограничения
- Если курьер в самолётном режиме, без интернета или выключил геолокацию, push не поможет. Но точки в очереди не пропадут и придут, когда появится связь.
- На iOS тихие push ненадёжны и ограничены системой. Опора там на значимые изменения локации (`stopOnTerminate: false`) и видимый push.
- Проверку состояния курьера на клиенте можно делать через `getState().lastLocationAt`: если `enabled` и точка старая, показать курьеру подсказку.

## 3. Heartbeat и нативный FCM-обработчик (реализовано)

### Heartbeat

Опция `heartbeatInterval` (секунды, 0 = выключено). Если за это время не записано ни одной точки (курьер стоит, `distanceFilter` не срабатывает), плагин сам записывает точку с флагом `heartbeat: true` и отправляет её на сервер.

```ts
await bm_geolocation.configure({ distanceFilter: 20, heartbeatInterval: 60 });
```

- Android: второй запрос геолокации по времени, без фильтра расстояния. Он будит процессор, пока курьер стоит. Точка пишется только если с последней прошло не меньше 90% интервала.
- iOS: таймер, пока приложение живо в фоне благодаря фоновой геолокации.
- Рекомендация: интервал в 2–3 раза меньше серверного порога (например, heartbeat 60 с и порог 3 мин). Чем короче интервал, тем больше расход батареи.

### Нативный FCM-обработчик (Android)

Сервер шлёт data-push с высоким приоритетом:

```json
{ "message": { "token": "<fcm_token>", "android": { "priority": "HIGH" }, "data": { "type": "wake_tracking" } } }
```

Обработка идёт целиком в нативном коде, без WebView. Если смена идёт (`enabled`), запускается foreground-сервис и сразу записывается свежая точка с `heartbeat: true`. Если смена не идёт, push игнорируется.

Как подключить:
1. В приложении должен быть настроен Firebase (`google-services.json`). Плагин объявляет `firebase-messaging` как `compileOnly`, версию подставляет приложение.
2. **Если своего FirebaseMessagingService нет**, ничего делать не нужно: работает `BmMessagingService` плагина (в манифесте у него низкий приоритет).
3. **Если сервис уже есть** (например, `@capacitor/push-notifications`, `@capacitor-firebase/messaging` или свой), Android доставляет сообщение только одному сервису. Тогда вызовите обработчик из него:

```java
@Override
public void onMessageReceived(RemoteMessage message) {
    if (BmFcm.handleMessage(this, message.getData())) return; // wake_tracking обработан
    super.onMessageReceived(message);
}
```

Ограничения:
- Запуск foreground-сервиса из фона разрешён для high-priority FCM, но для геолокации нужно разрешение «Разрешить всегда». Без него старт будет отклонён системой.
- На Xiaomi и Huawei push не доходит, если приложение принудительно остановлено пользователем. Для этого и нужна эскалация видимым push.
- iOS: нативного обработчика нет (тихие push ненадёжны). Опора на heartbeat, значимые изменения локации и видимый push.

## 4. Что ещё стоит сделать

- **Проверка на реальных устройствах** Xiaomi, Huawei, Samsung: экраны `openVendorSettings()`, heartbeat при блокировке экрана, wake по push при убитом процессе.
- **Серверная часть** (таблица, cron, отправка FCM) — в вашем бэкенде.
